# Configuration

Configuration is stored in each Zimlet's `config_template.xml` and can be applied with `zmzimletctl configure`.

## Routing

| Property | Purpose |
|---|---|
| `internalReportAddress` | Required recipient for messages that are not recognized as simulations. |
| `simulationReportAddress` | Recipient for recognized simulations. Required only when simulation detection is enabled and a message matches. |
| `internalSubjectPrefix` | Subject prefix for internal reports. |
| `simulationSubjectPrefix` | Subject prefix for simulation reports. |

## Moving reported messages

| Property | Purpose |
|---|---|
| `moveReportedMessage` | `true` or `false`. |
| `targetFolderId` | Zimbra folder ID. The default `4` is normally Spam/Junk. Verify this in your environment. |

The message is moved only after Zimbra accepts the report message. If sending fails, the original remains in its current folder.

## Simulation detection

| Property | Purpose |
|---|---|
| `simulationDetectionEnabled` | Enables classification. Disabled by default. |
| `simulationDisclaimerHeader` | Header containing provider disclaimer text. |
| `simulationDisclaimerRules` | Semicolon-separated OR rules. Inside one rule, pipe-separated markers must all occur. |
| `simulationDkimDomains` | Comma-separated DKIM domains. A verified `dkim=pass` match is accepted. |
| `simulationSourceIndicators` | Comma-separated strings expected in `Received` headers. Used together with an unverified DKIM signature match. |

Example rule:

```xml
<property name="simulationDisclaimerRules">provider-name|phishing simulation;provider-name|training email</property>
```

This means either both `provider-name` and `phishing simulation`, or both `provider-name` and `training email`, must occur in the configured disclaimer header.

Header values can be forged. Prefer verified `Authentication-Results` generated by your trusted mail infrastructure. Treat raw DKIM and IP indicators as supporting signals, not unquestioned proof.

## User-facing text

The button, subject prefixes, success notifications, and error messages are configurable. See either `config-examples/generic-en/` or `config-examples/generic-de/` for all available properties.

## Applying changes

```bash
zmzimletctl configure /path/to/classic.xml
zmzimletctl configure /path/to/modern.xml
zmprov fc -a zimlet
```

Users may need to reload the web client or sign out and back in.
